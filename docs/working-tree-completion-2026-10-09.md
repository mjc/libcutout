## Final implementation

Rust owns recording semantics, identity, queue capacity, material-change policy and persistence. Swift owns Apple acquisition, effects and presentation.

Marker save/clear and startup migration use desired/in-flight/acknowledged/latest-pending Rust intent. Admission does not wait for durable SQLite. One owner drives settlement. A delayed startup load or failure cannot overtake a newer accepted pairing attempt.

Core Location is created on a dedicated thread with an active run loop. Manager creation, callbacks, demand, permission observations and teardown use that owner. The native callback copies source and receipt clocks before Rust backpressure. Rust retains its lossless 64-observation budget, including the complete callback beyond saturation. Presentation and control mailboxes retain one latest value and one wake, rather than creating one Main task per sample. A real SQLite write lock proves all 65 material points survive while Main continues responding.

Availability, duration, restored map projections and music identity reads execute off Main. Cancellation and generations fence stale snapshots, errors, deleted/replacement rides and projection completion. Startup waits for authoritative restoration before history correlation; selected-device presentation receives its restored Rust snapshot before construction. Explicit historical deletion always targets the requested UUID.

Music observations enter a Rust-owned 64-slot FIFO before native Tasks are created. Full/exhausted admission produces typed failure without an unbounded task/payload backlog. Futures wake on predecessor settlement or retirement; no polling or blocked-thread queue is added. Lease epoch retirement and reducer reset are atomic. Write claim validates the exact recording token and enqueues under one Core acquisition. SQL waits hold neither the provider nor admission mutex.

A full 512-item pending-history buffer preserves its material baseline and exact retryable observation. Unverified/active old associations remain pending. Once Core proves the old ride closed or replaced, Rust retains its original UUID, transition ID, snapshot, kind and source/receipt clocks in a typed terminal failure receipt. This is never a recorded acknowledgement or reassociation with the new ride.

Each pending/skip-confirmation/retry transition also retains its original Rust capture target: NoCapture, Unavailable or Capture(generation). Swift passes the settled transition's target and actual SQL effective policy through the capture sink. In one BLE owner turn, Rust admission rejects retired/replacement targets before context or writer-health mutation. ContextOnly updates permitted pre-writer context; Recording returns and applies the actual recorder result. Main awaits a continuation and does not synchronously wait for BLE. Required history and capture receipts settle the observation before optional history readback. The lease may remain owned through that readback without holding up asynchronous Stop.

Player freshness has independent per-provider watermarks. A stale/equal player observation cannot suppress a needed history retry. Canonical player freshness is validated independently before history storage waits; completed UI publication remains usable when history admission/storage fails. A rejected required capture preserves the exact failure receipt while later player/history work remains usable. Explicit listening-history deletion clears retained diagnostics and fences late deleted metadata; ordinary readback refresh must preserve sticky failures. These receipts are process-local presentation diagnostics, not a new durable failure ledger.

Empty/dismissed music produces no compact inset, setup shell, placeholder artwork/artist or empty history section. Useful retained tracks keep recovery and provider commands. More retains explicit access, privacy/deletion and actual error feedback.

Ride no longer clamps requested Dynamic Type. Accessibility composition prioritizes speed, PWM, battery, status and actions, with secondary Rust-provided values in an accessible Readings presentation. Standard layout reserves scaled row/footer space. Main Ride remains fixed. History reload preserves the selected UUID even beyond the first page and invalidates deleted/filtered selections. The Simulator fixture creates 51 real saved routes through Rust APIs, not SQL or fabricated summaries.
